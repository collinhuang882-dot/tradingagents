## 本机启动

本工作区已准备好 Python 3.12.16、依赖与前端构建产物。在项目目录运行：

```powershell

```

## 配置真实接口

进入「数据与模型」：

1. 行情固定使用 **AKShare 1.20.38**，无需 Token、Tushare 积分或账户。
2. 填入模型服务的密钥、基础 URL 和模型名。基础 URL 例如 `https://供应商域名/v1`，程序追加 `/chat/completions`。模型需支持 function calling 和 JSON 输出。已有模型配置保留。
3. 点击「同步证券目录」。股票与行业独立保存，某个来源失败不影响另一项。当前已同步 5,225 只沪深股票、124 个申万二级行业。
4. 回到新建复盘选择「正式数据」，可按名称或代码搜索股票，按名称搜索行业。

模型也可以通过 `TRADING_LLM_KEY`、`TRADING_LLM_URL`、`TRADING_LLM_MODEL` 环境变量配置，环境变量优先。旧 Tushare 凭证保留在原本机设置文件中，但已不再使用或展示；没有调用 Tushare 作为备用接口。

页面保存的模型凭证位于本地 `data/settings.json`，没有额外加密；API 不回传密钥，日志和报告不记录密钥。请勿上传 `data/` 或把本应用直接暴露在公网。本版本不提供多用户认证。

### 数据来源与覆盖

| 数据 | AKShare 接口／来源 | 边界 |
|---|---|---|
| 沪深股票目录 | `stock_info_a_code_name`，交易所 | 过滤北交所，现有目录不是历史上市清单 |
| 交易日历 | `tool_trade_date_hist_sina` | 日期超出源日历覆盖时拒绝猜测 |
| 日线与复权 | `stock_zh_a_hist` 东方财富；失败时 `stock_zh_a_daily` 新浪备用 | 原始价格用于查看，后复权序列按复盘日价格归一后计算指标；不复权和复权数据必须来自同一来源 |
| 行业目录 | `index_realtime_sw` 二级行业 | 只把目录用于选择，不把当前指数报价写入历史报告 |
| 行业分析 | `index_hist_sw` 历史日线 | 展示行业指数涨跌幅、成交额变化率；未核验完整历史成分映射，成分涨跌家数、涨停数、领涨股标记不可用 |
| 公司公告 | `stock_notice_report` 东方财富 | 按日期拉取并筛选关注股票；只有日期而无时分的当天公告需时点核验；正文尚未取得时不作条款推断 |
| 美股指数 | `stock_us_daily` 新浪 `.INX`、`.IXIC` | 分别为标普500、纳斯达克综合，不用纳斯达克100替代综合指数 |
| 恒生指数 | `stock_hk_index_daily_sina`，`HSI` | 仅纳入截止前已完成的交易时段 |
| 发改委、证监会 | 原有两个官方栏目采集器 | 与行情供应商无关，继续保留；每栏目最近 12 条，不是全量政策档案 |

单位统一：东方财富成交量为手、成交额为元；新浪成交量为股、成交额为元。内部转换后，网页和导出统一使用股／元。申万历史指数成交额绝对单位未核验，因此仅输出同源相邻交易日的变化率，不猜测人民币绝对值。

AKShare 来源可能限流、断网或变更格式。每个 SDK 请求放在受限子进程中，最多等待 55 秒；公告请求 45 秒。成功结果缓存在 SQLite，键含接口、参数及 SDK 版本。股票／行业目录、交易日历缓存 24 小时，行情及公告默认 1 小时；不会用今天的实时行情填补历史缺口。

政策检索仍按截止时间、关键词和 `app/policy_topics.json` 主题表筛选，最多 20 条事件。官方栏目启动时与任务前更新，30 分钟内复用；失败与没有相关结果分别显示。文本 PDF 可解析，扫描件不做 OCR。

旧报告及原证据保持不变。旧来源失败任务不能混用 AKShare 检查点恢复，需要复制参数重新生成。股票代码沿用 `600519.SH` 等格式，新行业代码使用 `ak:sw:801125`，不会与旧行业目录混淆。

## 已实现的产品流程

- 新建：最多 10 股、5 个行业，交易日／截止时间校验、数据预检、幂等提交。
- 执行：八个职责节点、阶段进度、错误提示、取消、检查点恢复、固定快照、版本重跑。
- 查看：概览、行业、个股日 K 与成交量、政策与外围、多空与风险、证据六个页面。
- 筛选：股票／行业／风险组合，政策机关／类型／日期／正文状态，证据来源／质量，关键词与数值排序；地址保存筛选状态。
- 证据：引用编号打开详情，显示原始数值或正文、时间、来源、质量与快照编号。
- 导出：完整报告或全部匹配结果；Markdown（含图时 ZIP）和 Word；保留原报告概览、依赖证据、缺口、版本及筛选范围。
- 历史：按日期、对象、状态筛选和分页，复制参数重跑保留旧报告。

图中的 60 分钟、资金流、个性化仓位／止盈止损、估值与评分在 PRD 中属于 **P1**，本次没有伪造这些数据或输出。

## 技术结构

```text
React + TypeScript + Vite
        │ HTTP JSON / 轮询
FastAPI ── SQLite WAL（任务、原始快照、证据、报告、检查点）
        │ 独立 worker，进程锁和心跳
LangGraph
数据核验 → [行业分析 ∥ 量价分析 ∥ 政策外围]
         → [多头证据 ∥ 空头反证] → 风险审查 → 报告整合
        │
AKShare / 官方采集器 / 模型 get_evidence 工具
        │
同一份结构化报告 → 网页 / Markdown / python-docx
```

数据核验和报告整合采用确定性程序；六个解释性节点在正式模式中调用模型。政策 Agent 调用 `get_evidence` 读取本次已经过时间检查的政策正文和外围证据。多空读取同一证据集合，风控读取多空输出；引用 ID、对象和新增数值经过校验。每节点最多 8 轮工具调用，任务最多 60 次逻辑模型请求，预算 15 分钟。底层 HTTP 重试另计，最多 2 次。

原始数据和结果在 `data/app.db` 中持久化，下载文件在 `data/exports/`。恢复同一任务复用检查点；新任务重新获取数据，不把旧报告快照当成当前行情。模型用量记录实际调用次数和供应商返回的 token；未配置价格时不估算费用。

这是参考 [TauricResearch/TradingAgents](https://github.com/TauricResearch/TradingAgents) 多角色思路、按本 PRD 独立实现的 A 股应用，不是原仓库已具有这些 A 股政策能力的声明。

## 新环境安装

需要稳定版 Python 3.12、Node.js 20.19+ 或兼容版本。不要使用 Python 预发布版本。

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
cd frontend
npm.cmd ci --cache ../.npm-cache
npm.cmd run build
cd ..
.\run.ps1
```

`requirements.lock.txt` 与 `frontend/package-lock.json` 固定已验收的依赖版本。前端开发命令为 `npm.cmd run dev`，代理后端 8765 端口。
